Sylve v0.3.2 rebuilds clustering on encrypted, authenticated node-to-node traffic and adds Podman containers, a FreeBSD + Sylve installer, NFS shares, VLAN filtering on standard switches, and SLIRP networking for VMs. It includes more than 180 commits since v0.3.1.

Clusters upgrade with a one-time rebuild: read the [upgrade steps from 0.3.0 or 0.3.1](https://sylve.io/guides/data-center/cluster/#upgrade-from-030-or-031) before upgrading any node.

## Upgrade notes

- **Clusters rebuild once.** v0.3.2 can't share a cluster with v0.3.0 or v0.3.1. Upgrade every node, ideally together; guests keep running. Each upgraded node waits until a majority of the old voters is upgraded. Then the most up-to-date member founds the new cluster from its own database, and the others rejoin it on their own. Cluster-wide operations pause until then. The old Raft state is kept in `raft.pre-1` under `dataPath`.
  - Take a ZFS snapshot of the dataset that holds `dataPath` on every node first. Rolling back to v0.3.0 or v0.3.1 isn't supported other than by restoring those snapshots.
  - Make no changes while stopping the nodes. v0.3.0 and v0.3.1 don't record which changes each node's database holds, so a change committed just before the cluster stopped can be lost.
  - If a majority of the old voters is gone for good, run `sylve datacenter cluster recover-quorum` on an upgraded survivor. It founds the new cluster from its database on its next start. The same goes for a node that was rejoining when the founding node was lost for good.
  - A member whose hostname another member already has, or whose guest IDs another member uses, is refused when it rejoins. It keeps running standalone with its guests, and rejoins on its own once it is renamed (restart Sylve after renaming) or the ID is changed.
- **Join keys replace the cluster key.** Generate a key on any member and join through that member's address. A key admits one node; generating a new one replaces it, and a join or any removal spends it. Old cluster keys and scripts that use them stop working, and the cluster key is no longer an API credential.
- **Cluster traffic uses mutual TLS.** Raft and the internal cluster API are encrypted, and each member is pinned to its certificate. A reinstalled member, or one whose `sylve.db` was restored on another machine, must be removed and joined again.
- **Hostnames must be unique in a cluster.** A node whose hostname a member already has can't join.
- **A member that meets a cluster change it can't apply now stops** and must be upgraded. Older releases logged the change and skipped it.
- **Jail VLANs from v0.3.1** become access ports on that VLAN. On a switch without VLAN filtering, such a jail won't start (`vlan_policy_requires_filtered_switch`) until filtering is enabled or the VLAN is cleared.
- **PCI passthrough** syncs `loader.conf` only while the Virtualization service is enabled.
- **Containers** need Podman and the `cni-dnsname` plugin. The installer installs Podman by default. CPU and memory limits need `racct`.
- **Samba** no longer syncs the admin user implicitly, and share principals are restricted to PAM users.
- **API:** a request for another node names it in the path, `/api/nodes/<node-id-or-hostname>/<route>`. The `X-Current-Hostname` header is gone, and so are cluster tokens (`X-Cluster-Token`). `/cluster/join-key` is now a `POST` that generates a key and returns it with the address to join through. `POST /cluster/resync-state` is gone. Audit records gain `originNode` for requests forwarded from another member.

## Clustering

- Encrypted and authenticated all node-to-node traffic with mutual TLS, and pinned each member to its certificate. Raft runs over TLS on `8180`, and the internal API on `8184`.
- Replaced the cluster key with single-use join keys that any member can generate. A join can go through any member.
- Rebuilt joining: a refused join leaves the node exactly as it was. A join that can't reach the cluster keeps retrying, also after a restart. The joining node catches up as a non-voter before promotion. A joining node that makes no progress for 10 minutes is removed, and asks again when it's back.
- Rebuilt peer removal and leave around a single removal path on the leader. Removal no longer needs to contact the target: the removed node notices and resets itself, keeping its guests. A leave the leader can't confirm stays pending and can be cancelled with **Cancel Leave**.
- Added `sylve datacenter cluster recover-quorum` to recover a cluster whose majority is gone for good.
- Made replicated state exactly-once, so a member applies each committed change once, including across restarts.
- Fixed readdressing in two-voter clusters, and let `recover-ip` move an interrupted readdress to any IP the node still has.
- Routed requests for another node through one forwarding layer, named by node ID or hostname in the path. An administrator's forwarded request is audited with the node it came through.
- Replaced the per-operation internal routes with one typed internal RPC layer.
- Made member health follow the verified leader.
- Simplified the shared guest-ID registry: the cluster releases a removed node's claims by itself, and `guest-ids reclaim` takes only `--id`.
- Fixed replication policy deletion so the owner is cleaned up before the targets. Kept a new replication policy's running guest from being fenced before any target could be promoted.
- Resumed interrupted backup-target restores and released queued backup and restore jobs after a node starts without quorum.
- Stopped SSH stderr from corrupting parsed remote output in backups, and improved prune error handling.
- Removed the state-resync and repair machinery that the new consensus guarantees made unnecessary.

## Containers

- Added Podman containers, run like jails, with per-pool container stores and a per-pool Podman service.
- Added container stacks; a stack's relative folders are shared as datasets under the stack.
- Added containers to the resource tree and guest pickers.
- Checked the container runtime before enabling containers, and showed container requirements and errors on the Services page.
- Rejected CPU and memory limits without `racct`, with a clear error message.

## Virtual machines

- Added SLIRP user-mode networking for VM NICs. Inbound port forwarding is not supported yet.
- Added CSMWrap boot support.
- Added recovery of orphaned libvirt configurations.
- Moved CPU pinning to native libvirt XML, and enforced the `hw.vmm.maxcpu` limit on creation.
- Fixed serial and VNC console reconnection across lifecycle actions.
- Fell back to the guest agent directly when libvirt sync fails.
- Used the host's live RAM total for guest memory limits, and sampled usage statistics without blocking other VM operations.
- Dropped unsupported bridge port isolation from domain XML.

## Jails

- Added package management and vulnerability monitoring for jails.
- Added guest information to jail summaries, and jail restart controls.
- Queued jail creation, and allowed importing or renaming existing datasets during creation.
- Added non-interactive command execution from the CLI.
- Included descendant processes in jail CPU and memory statistics.
- Fixed console reconnection across lifecycle actions.
- Fixed bootstrap pkgbase ownership, preserved the pkg database, cleaned up legacy bases, and tolerated mtime mismatches from pkg older than 2.8.0.
- Selected `allow.chflags` by default when creating a jail.

## Networking

- Added VLAN filtering to standard switches, and showed VLAN policy across switch, jail and VM tables.
- Added multiple static addresses on standard switches, and hardened switch edits, rollback, MTU reconciliation and dependency checks.
- Added persistent host interface IP configuration with rollback.
- Added PF rule options and ordered raw firewall rules.
- Added the ClouDNS provider for dynamic DNS.
- Showed where named network objects are used.
- Fixed WireGuard status going stale, and enlarged the peer form.
- Fixed IPv6 management listener binding, a bridge-member IPv6 cleanup race, and DHCP lease address comparison.
- Reduced idle telemetry process forks.

## Storage and file services

- Added NFS shares.
- Added Samba Active Directory and Kerberos support, global configuration, and extra share configuration. Fixed stale share caches and unmounted datasets.
- Added bounded extra native iSCSI target configuration. Fixed shared portal listeners and recovery after a failed cold start.
- Added ZFS pool scrub scheduling and history, and bulk deletion of periodic snapshots.
- Refused deleting ZFS pools that are in use.
- Fixed SMART collection and wearout reporting, acknowledged previously seen error counts, and added SMART counter previews to notification rules.

## System, installation and authentication

- Added a FreeBSD + Sylve installer with unattended installation. It enables `ntpd` and installs Podman by default.
- Added host package updates and standalone Sylve updates.
- Added declarative first-boot provisioning.

- Recovered lifecycle tasks stranded by an interrupted startup.
- Made the PAM service configurable, and supported externally managed PAM accounts and groups.
- Enforced the 72-byte bcrypt password limit, made PAM home directory removal opt-in, and allowed usernames shorter than three characters.
- Reported ignored admin password updates in the configuration, with a hint about `forcePasswordReset`.
- Added confirmations for guest power actions.
